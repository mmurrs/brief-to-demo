# Demo Readiness

Use this after the golden path works. Prioritize deterministic behavior and clarity over last-minute feature expansion.

## Product integrity

- The demonstrated workflow matches the Demo Contract.
- Source-backed facts, inferences, assumptions, and simulations remain distinguishable.
- The prototype does not imply integrations, automation, security, or operational readiness that it does not have.
- The end state demonstrates the intended outcome, not merely successful navigation.

## Functional preflight

- Startup instructions work from a clean terminal.
- The application loads without visible errors.
- Seed data appears consistently.
- Every action in the golden path works in sequence.
- Refresh behavior is understood.
- A reset restores the opening state.
- No visible control on the route is broken or misleading.

## Presentation preflight

- The browser starts on the intended opening screen.
- The interface works at the expected window size.
- Text, states, and controls are legible without explanation.
- Demo data tells one coherent scenario.
- Notifications and unrelated windows are removed from the path.
- The presenter can complete the route without searching for the next action.

## Runbook

Prepare a short sequence:

1. **Frame:** State the user, current pain, and desired outcome.
2. **Orient:** Explain the starting state and why the workflow begins.
3. **Show:** Perform the golden path, naming the value of each state change.
4. **Prove:** Call out the one or two moments that validate the solution thesis.
5. **Close:** Restate the outcome, boundaries, and most valuable next step.

## Failure plan

- Know the exact restart command.
- Keep a deterministic reset available.
- Capture one current screenshot of each critical state when practical.
- If a nonessential element fails, skip it and return to the proof path.
- If the prototype cannot demonstrate a claim, describe it as a limitation rather than pretending it worked.

## Stop rule

Stop adding features when the complete path is reliable and every contract claim has visible proof. Spend remaining time rehearsing, simplifying, and removing failure points.
